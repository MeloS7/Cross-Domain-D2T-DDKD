# Cross-Domain, Multi-Task Data-to-Text Generation without In-Domain Training Data

**Yifei Song · Kun Efimov-Zhang · Claire Gardent**

**Findings of EMNLP 2026**

[Paper](https://arxiv.org/abs/2608.23391) · [PDF](https://arxiv.org/pdf/2608.23391) · [Experiment guide](docs/EXPERIMENTS.md) · [Data sources](docs/DATA_SOURCES.md)

This repository accompanies our study of data-to-text generation across five
domains and multiple input formats, without target-domain reference texts.
**Data-driven knowledge distillation (DDKD)** trains small students on texts
generated by large teachers, using real structured inputs and structural
subsampling/perturbation.

The release includes prepared training examples, test inputs, saved generations,
LLM and human annotations, and content coverage evaluations. Saved results can
be analyzed without a GPU or an API key.

## Quick start

Run from the repository root:

```bash
cd Cross-Domain-D2T-DDKD
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-analysis.lock.txt
unzip -q data.zip

python src/eval/analyze_judge_output.py \
  --input_file data/model_outputs/quintd/gsmarena/eval_res/zero_shot/gsmarena_zero_shot_gpt4.1_gpt-5.1.jsonl

python src/eval/IAA_compute.py --base_dir data/human_eval
```

All commands below use this inner project directory as the working directory.
The analysis dependency snapshot is tested with Python 3.12. For independently
managed environments, use `requirements.txt` instead. GPU dependencies are
installed separately.

The example reports **1.050 errors per output** and a **57.0% error rate**.
Human IAA reports overall alpha values of **0.3692** (token), **0.5784**
(instance), **0.9023** (system), and **0.6926** (summary).

## Released data

[data.zip](Cross-Domain-D2T-DDKD/data.zip) is approximately **85 MiB compressed**
and **1.32 GiB extracted**. It contains 507 files, without macOS metadata.
[data_manifest.json](Cross-Domain-D2T-DDKD/data_manifest.json) lists public
relative paths, record counts, file checksums, and the archive checksum.

| Directory after extraction | Contents |
| --- | --- |
| `data/test/quintd/{domain}/` | QUINTD-1 test inputs and tables; 100 examples per domain |
| `data/train/quintd/{domain}/` | Prepared base, subsampled, perturbed, and mixed inputs and teacher-generated examples |
| `data/train/SFT/` | Prepared WebNLG training/development examples for Qwen and Gemma |
| `data/train/quintd5/{domain}/` | 500 development inputs and ZS/SFT teacher examples per domain |
| `data/model_outputs/quintd/{domain}/outputs/` | Saved generations from the main experiments |
| `data/model_outputs/quintd/{domain}/eval_res/` | Faithfulness annotations and `*_cc_*.jsonl` coverage evaluations |
| `data/model_outputs/quintd5/{domain}/` | Outputs and GPT-5.1 annotations for the 500-input experiments |
| `data/human_eval/` | Selected inputs/outputs, three anonymous annotators' labels, and annotation tools |
| `data/results/` | Main-table error counts and the annotation paths used to calculate them |

Domains are `gsmarena`, `ice_hockey`, `owid`, `weather`, and `wikidata`.
Public filenames use `sub` for subsampling and `pert` for perturbation.
QUINTD-5 denotes the paper's setting with 500 real development inputs per domain.

The human study contains **60 inputs**, **240 system outputs**, and three
annotation files with 240 records each. Its original indices, labels, and
generated texts are preserved.

### Formats

- **Training/test examples:** JSONL records containing `messages`.
- **Model outputs:** JSONL records containing `response`.
- **Input tables:** JSONL records containing `formatted_input` and source fields.
- **Faithfulness annotations:** `table_idx` and `annotations`; error types are
  `0` incorrect fact, `1` not checkable, `2` misleading, `3` other.
- **Coverage annotations:** `coverage_score`, `estimated_coverage_ratio`, and
  `parse_error`; invalid records are excluded from coverage statistics.
- **Human annotations:** `instance_id`, `domain`, `table_idx`, `system`,
  `output_text`, and `errors`; `[SUM]` labels are handled separately.

## Generate and evaluate new text

API scripts use an OpenRouter-compatible endpoint. Set credentials in your
shell; no credential file is required:

```bash
export OPENROUTER_API_KEY='YOUR_API_KEY'
# Optional: export OPENROUTER_BASE_URL='https://openrouter.ai/api/v1'
mkdir -p results

python src/inference/infer_gpt41.py \
  --input_file data/test/quintd/gsmarena/gsmarena_test_chat_format.jsonl \
  --output_file results/gsmarena_gpt41_responses.jsonl \
  --model openai/gpt-4.1 --temperature 0 --max_tokens 2048 --seed 42

python src/eval/LLM_eval_OpenRouter.py \
  --input_file results/gsmarena_gpt41_responses.jsonl \
  --output_file results/gsmarena_gpt41_gpt51.jsonl \
  --input_table data/test/quintd/gsmarena/test_input_table.jsonl \
  --model openai/gpt-5.1 \
  --config src/eval/eval_prompt_config.yaml \
  --dataset_name quintd_gsmarena_test --model_name gpt-4.1
```

These commands make API requests. Input tables and generations must have the
same row order and count. Failed API calls or invalid new judgments cause a
nonzero exit instead of being recorded as error-free generations. For the
examples under `script/eval/`, set `OUTPUT_FILE` to a path under `results/`.

## Train and run local models

The portable examples under `script/swift/` use
[MS-Swift](https://github.com/modelscope/ms-swift) and vLLM. Configure model,
dataset, adapter, and output locations through environment variables. For
example:

```bash
export MODEL='Qwen/Qwen3-1.7B'
export TRAIN_DATASET='data/train/quintd/wikidata/qwen3_32B_zero_shot/dev_chat_format_zero_shot_as_paper_qwen3_32B_base.jsonl'
export OUTPUT_DIR='results/wikidata_base'
export MODEL_NAME='qwen3_wikidata_base'
MODE=base MAX_LENGTH=8192 bash script/swift/swift_sft_distill_example.sh
```

See [training settings](docs/EXPERIMENTS.md#training-and-inference) for model
family differences and required variables. The examples require a compatible
GPU environment; this release's CPU dependency snapshot is not the historical
GPU training environment. Trained checkpoints and the full raw-data collection
pipeline are not included. Prepared training examples are supplied.
